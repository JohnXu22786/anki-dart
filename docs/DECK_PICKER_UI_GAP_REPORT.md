# Deck Picker Flutter surface gap report

Baseline: AnkiDroid 2.25.3 at `d9bf072f814a0c37d30a694192593b31ff2df875`, matching the repository's approved source pin. This report maps the portable Flutter surface to shared Dart contracts and records the remaining host boundary.

| Screen or flow | Shared Dart contract | Flutter mapping | Labels and accessibility | Remaining host boundary |
|---|---|---|---|---|
| Deck tree, due counts, filter and collapse | `DeckNode`, `DeckFilters`, `DisplayDeckNode.filterAndFlattenDisplay()` (`lib/src/deck_node.dart`, `deck_filters.dart`, `display_deck_node.dart`) | `DeckPickerScreen` converts the host tree to shared nodes, delegates filtering and flattening, and renders the visible rows and new/learning/due counts. Search appears when the host list has at least ten decks; an open search remains closable if refresh lowers that count or fails. | English ARB labels, count semantics, selected row semantics, expand/collapse tooltips, keyboard-focusable Material controls, right-click context menu. | Collection hierarchy/count projection, current deck ID, collapsed-state persistence, selection and refresh effects are supplied by `DeckPickerRepository`. |
| Study and deck selection | `planDeckPickerSelection()` and existing study navigation projections | Row selection calls `selectDeck(id)`; row and selected-deck study controls pass the unchanged ID to `study(id)`. | Explicit Study label and play-button tooltip. | Host executes shared selection effects, opens the study screen and applies scheduler behavior. |
| Deck context actions | `DeckPickerSelectionEffectPlan` and existing deck action plans for host operations | Context menu preserves the pinned action order and filters dynamic-deck-only, regular-deck-only, buried-card, and preference-gated reminder actions using injected host state. | Localized action names; menu is reachable by touch, keyboard, or secondary mouse click. | Menu actions remain typed `DeckPickerAction` calls into the host. Delete, rename, browse, export, scheduler, persistence, and navigation are not implemented in widgets. |
| Add menu and create deck | Existing deck creation/navigation callbacks | Floating menu order follows shared deck, regular deck, filtered deck from `DeckPickerFloatingActionMenu.kt`; create-deck name is forwarded unchanged. | Localized labels, semantic FAB tooltip, focusable controls. | Shared-deck browsing and deck creation are host actions. |
| Filtered-deck options | `FilteredDeckOptions` and search/filter projections in `lib/src/filtered_deck_options.dart`; operation plans in `deck_picker_filtered_deck_operation_plan.dart` | The host-projected `FilteredDeckOptions` seeds title, input values, backend order enum numbers, localized card-order labels, and scheduling switches. The options screen forwards edited fields as a typed `FilteredDeckRequest` without parsing queries or implementing scheduler rules. | Localized labels, accessible switches/fields, scrollable narrow layout and constrained wide layout. | Host validates names and queries, builds search/backend models, performs the scheduler operation, reports errors and returns to the refreshed deck list. |
| Loading, empty, unavailable, and failure | No widget data or collection state is persisted locally | Future-backed states show loading progress, no-decks, no-results, retryable load error, or explicit collection-service unavailable copy. | Loading progress has an accessibility label; retry and refresh actions are labeled. | Platform repository provides actual data and error classification. |

## Native source and resources inspected

- `AnkiDroid/src/main/java/com/ichi2/anki/DeckPicker.kt` and `deckpicker/DeckPickerViewModel.kt`: deck selection, screen navigation, empty/loading list and search threshold.
- `AnkiDroid/src/main/java/com/ichi2/anki/DeckPickerFloatingActionMenu.kt`: shared deck, create deck, and filtered deck action order.
- `AnkiDroid/src/main/java/com/ichi2/anki/deckpicker/DisplayDeckNode.kt` and `DeckFilters.kt`: hierarchy filtering and displayed count behavior, already projected by shared Dart contracts.
- `AnkiDroid/src/main/java/com/ichi2/anki/dialogs/DeckPickerContextMenu.kt` and `contextmenu/DeckPickerMenuContentProvider.kt`: action names, order and dynamic/buried conditional availability.
- `AnkiDroid/src/main/java/com/ichi2/anki/filtered/FilteredDeckOptionsFragment.kt`, `FilteredDeckOptionsState.kt`, and `FilteredDeckOptionsViewModel.kt`: filter/order/reschedule/allow-empty surface and host-owned build flow.
- `AnkiDroid/src/main/res/menu/deck_picker.xml`, `menu/deck_picker_dialog_menu.xml`, `layout/include_deck_picker.xml`, and `layout/fragment_filtered_deck_options.xml`: source menus and screen structure. No upstream images or translated resource files were copied; screen labels are newly authored English ARB resources.

The implementation covers the Flutter feature surface and typed boundaries. A native/backend adapter that supplies deck state and implements each repository callback remains necessary before platform builds can show a real collection.
